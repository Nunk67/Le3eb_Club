# 陪玩等级测算验算说明

## 1. 目的

用于核对“等级分与衰减比例是否合理”，并明确如何按当前规则解释测算结果。

## 2. 验算公式

## 2.1 基础分

- 订单积分：`接单收入 / 20`
- 周总积分：`订单积分 + 活跃积分 + 评价积分 + 服务用户积分`

## 2.2 衰减与结余

- 周衰减积分：`中位积分 * 等级衰减率`
- 周结余积分：`周总积分 - 周衰减积分`

## 2.3 升降级周数

- 升级周数：`(下一等级起始积分 - 当前起始积分) / 周结余积分`
- 仅衰减降级周数：`(本级中位积分 - 下一级上限积分) / 周衰减积分`

## 2.4 摆烂累计

对“零订单扣除积分1~4”的结余采用累计：

- 第 1 周：`活跃积分 - 周衰减积分 - 50`
- 第 2 周累计：`第1周结余 + 活跃积分 - 周衰减积分 - 100`
- 第 3 周累计：`第2周结余 + 活跃积分 - 周衰减积分 - 150`
- 第 4 周累计：`第3周结余 + 活跃积分 - 周衰减积分 - 200`

## 3. 当前表内数据验算结论

按测算表提供的样本（活跃积分=100）：

- 周总积分、衰减积分、结余积分计算链条是自洽的。
- 升级周数和降级周数计算方式一致且可复算。
- “摆烂情况”是累计模型，不是每周独立模型。

## 4. 与规则定稿的差异提示

下列差异会影响“最终合理性”判断：

- 表中活跃积分按 `100` 固定；规则上限是 `150`。
- 表中未显式处理“刚升级当周不衰减”。
- 表中出现负分延续；规则为 `points <= 0` 停止衰减与惩罚。

建议：保留当前表做趋势分析，同时新增“规则一致版”测算列进行对照。

## 5. 规则一致版测算最小修正

在不改表结构的前提下，新增以下开关列即可：

- `activity_cap_mode`：`100` 或 `150`
- `skip_decay_on_upgrade_week`：`0/1`
- `stop_decay_penalty_at_zero`：`0/1`

并将结余公式改为：

- `new_points = max(0, old_points + week_gain - decay - penalty)`

其中：

- 若本周升级且开关打开，则 `decay=0`
- 若 `old_points<=0` 且开关打开，则 `decay=0` 且 `penalty=0`

## 6. 算法门禁验收项（ALG）

以下条目为自动开发闭环的强制门禁项，供 validators 与反馈循环直接引用：

- `ALG-01` 周归属正确：所有事件按 `UTC+3` 归属 `week_key`。
- `ALG-02` 评分生效正确：未评按 5 星；改分按生效时间归属周；冲销与重入可追踪。
- `ALG-03` 回复率正确：仅 Online 样本，公式 `已回复/收到`，档位映射 `35/20/5/0` 正确。
- `ALG-04` 接单率正确：仅 Online 样本，公式 `5分钟内接单成功/可接邀请`，分母 0 按 0 分。
- `ALG-05` 衰减正确：按等级衰减率执行，且升级当周不衰减。
- `ALG-06` 惩罚正确：连续无单惩罚 `50/100/150/200`，封顶 200。
- `ALG-07` 停扣正确：`points <= 0` 时衰减与惩罚均停止。
- `ALG-08` 入账顺序正确：加减分按 `event_time` 顺序入账，结算日发分前事件可顺延。

## 7. 验收清单

- 各等级样本行复算误差为 0
- 升级/降级周数与公式一致
- 摆烂四周累计链条正确
- 规则一致版开关开启后，结果符合定稿口径
- `ALG-01` 到 `ALG-08` 全部通过，方可进入下一阶段
